Patch. HTTP MCP `wiki_log_append` is independently verifiable when `log.md` exceeds the 256 KiB full-read cap.

- `wiki_log_append` writes a `skillwiki-log-event/v1` record first, then the `log.md` projection block. Success returns a receipt (`operation_id`, `event_path`, hashes, `s3_verified`). Verify with `wiki_read_page(event_path)`. Do not require reading `log.md`.
- Replay of the same `operation_id` + exact block returns `appended=false`. Missing projection marker is repaired (`projection_repaired=true`).
- Optional client `operation_id` (64 lowercase hex). Default is `operationId("skillwiki-mcp-log-append-v1", [date, exactBlock])`.
- `wiki_read_page` `PAGE_TOO_LARGE` now includes `sha256`, `byte_length`, and `s3_verified`. Optional `tail_bytes` (1..262144) returns a UTF-8-safe tail without raising `PAGE_TOO_LARGE`.
- Skills (`skillwiki-mcp`, `using-skillwiki`) tell agents to verify via the event path.
