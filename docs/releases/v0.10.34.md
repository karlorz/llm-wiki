# skillwiki v0.10.34

Patch release. Stops `install:activation` from writing user-scope Claude/Codex
instruction files when those harnesses already activate via plugin SessionStart.

## Fixes

- **Activation install skips hooked harnesses:** `npm run install:activation`
  now installs **Grok only** by default (`~/.grok/skillwiki.md` + marker in
  `AGENTS.md`). Claude Code and Codex already inject `using-skillwiki` through
  plugin SessionStart hooks (`hooks/session-start`, `hooks/session-start-codex`);
  writing `~/.claude/CLAUDE.md` / `~/.codex/AGENTS.md` double-activated context
  and polluted user-scope files.
- **Cleanup of prior dual-target installs:** re-running `install:activation`
  removes residual Claude/Codex skillwiki marker blocks and matching
  `skillwiki.md` copies. Non-marker content in those files is preserved.
- **Opt-in fallbacks:** `--with-claude` / `--with-codex` remain available only
  when the plugin SessionStart path is unavailable. `--check` fails if Claude
  or Codex still carry a residual activation block.
- **Docs:** `using-skillwiki` Activation File section documents Grok-only
  default and the Claude/Codex hook ownership model.

## Rollout

After upgrading:

```bash
npm install -g skillwiki@0.10.34
skillwiki --version
# From a source checkout of this release:
npm run install:activation
# Removes residual ~/.claude/CLAUDE.md marker if present; keeps Grok activation.
```

Claude plugin users: keep relying on SessionStart — do **not** re-add
`@skillwiki.md` to `~/.claude/CLAUDE.md`. Update the plugin channel as usual:

```bash
claude plugin update skillwiki@llm-wiki
```
