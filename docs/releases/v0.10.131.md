# v0.10.131: Codex direct SkillWiki MCP packaging

## Changes

- Bundle a Codex-native `skillwiki_native` HTTP MCP declaration alongside the
  existing skills and hooks. Materialize the canonical `codex-mcp.json` into
  the installed Codex plugin's `codex-mcp.json` and reference it from the manifest.
- Use a fixed HTTPS endpoint and `bearer_token_env_var: SKILLWIKI_MCP_TOKEN`.
  Codex CLI 0.164.0 preserves shell placeholders literally and ignores
  Claude-style `headers`, so its declaration is maintained separately.
- Require reading `skillwiki-mcp` before the first wiki MCP call. Distinguish
  direct native MCP from hosted `codex_apps` OAuth, prefer the configured direct
  route in native Codex, and stop on authentication or permission failure before
  switching connections or identities.
- Add regression checks for a missing or drifted MCP asset, unsupported settings,
  manifest wiring, and skill-first connection selection.

## Upgrade boundary

Install v0.10.131 through the plugin channel to receive these changes.
Existing v0.10.130 installations contain skills and hooks only. A fresh
session must receive the refreshed plugin and an operator-provided bearer in
its launch environment. Tokens stay private and outside the package.

A hosted OAuth reconnect renews the hosted app account. Direct MCP setup is a
separate operation. A successful parser check proves configuration loading;
verify authentication with a read-only MCP call before using the new connection.
