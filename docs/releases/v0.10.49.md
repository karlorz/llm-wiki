# skillwiki v0.10.49

Patch release. Stops Grok from opening `~/skillwiki.md` (or a cwd-relative
`skillwiki.md`) when it follows the SkillWiki activation marker.

## Fixes

- **Grok activation marker uses an explicit home path:** `npm run install:activation`
  now writes `Read @~/.grok/skillwiki.md for SkillWiki activation context.`
  (ADR-3). Relative `@skillwiki.md` (ADR-6) made Grok `read_file` `$HOME/skillwiki.md`
  or `$CWD/skillwiki.md`. Opt-in `--with-claude` / `--with-codex` markers use
  `@~/.claude/skillwiki.md` and `@~/.codex/skillwiki.md`.
- **`skillwiki doctor` `activation_grok`:** read-only warn when `~/.grok/skillwiki.md`
  is missing, the AGENTS.md marker is still `@skillwiki.md`, or the compact file
  drifted from the template. Suggests `npm run install:activation` from the
  llm-wiki repo. Does not write `AGENTS.md`.
- **`using-skillwiki` no longer auto-invokes at session start.** The compact
  `~/.grok/skillwiki.md` is session-start context. The full skill is for
  vault/wiki/setup work only.
